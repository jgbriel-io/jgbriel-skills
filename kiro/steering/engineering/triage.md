# Triage

Move issues through a state machine of triage roles. Every comment/issue posted during triage **must** start with:

```
> *This was generated by AI during triage.*
```

## Roles

Category: `bug` | `enhancement`

State: `needs-triage` | `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix`

Every triaged issue carries exactly one category + one state role. Label strings may differ per project — mapping defined in project's `CLAUDE.md`.

## Triage a specific issue

1. **Gather context.** Read full issue (body, comments, labels). Parse prior triage notes.
2. **Recommend.** Category + state recommendation with reasoning. Wait for direction.
3. **Reproduce (bugs only).** Trace relevant code, run tests. Report: repro confirmed, failed, or insufficient detail.
4. **Grill (if needed).** Run a grill-with-docs session to flesh out.
5. **Apply outcome:**
   - `ready-for-agent` → post agent brief
   - `ready-for-human` → same structure, note why can't be delegated
   - `needs-info` → post triage notes (template below)
   - `wontfix` bug → polite explanation, close
   - `wontfix` enhancement → write to `.out-of-scope/`, link, close

## Needs-info template

```markdown
## Triage Notes

**What we've established so far:**
- point 1

**What we still need from you (@reporter):**
- question 1 (specific and actionable)
```

## Quick state override

If user says "move #42 to ready-for-agent", trust them and act directly. Confirm what you're about to do, then act.

## Resuming a session

Read prior triage notes, check if reporter answered outstanding questions, present updated picture before continuing.
